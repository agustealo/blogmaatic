# Operator API

Slice 8 exposes Blogmaatic's existing publication automation authorities through a small authenticated HTTP surface. The API does not own publication, automation, schedule, or workflow truth. It is an adapter over `@blogmaatic/control-plane` and the durable automation runtime.

## Authority boundary

```text
Operator / Integration
        |
        v
@blogmaatic/operator-api
        |
        +--> Control Plane
        |      registry
        |      event inbox
        |      scheduler
        |      run registry
        |
        +--> Durable runtime
               status
               approval
               terminal result
```

The API must not query SQLite directly, invent a second scheduler, or reinterpret workflow state. Reads and writes go through the canonical control-plane store/contracts and runtime interfaces.

## Authentication

The first deployable authorizer is `StaticBearerAuthorizer`.

Credentials are supplied to the process by deployment configuration. Plaintext bearer tokens are hashed immediately with SHA-256 and only digests are retained by the authorizer. Incoming token digests are compared with `timingSafeEqual`.

Tokens must be at least 32 characters and are associated with:

- an immutable principal id
- `operator` or `integration` principal kind
- explicit permissions
- optional approval roles
- optional event-source identity

The API never returns configured credentials.

`StaticBearerAuthorizer` is an adapter, not a user-account system. A later identity provider can implement the same `OperatorAuthorizer` contract without changing route authority.

## Permissions

The initial permission set is:

- `automations:read`
- `automations:write`
- `schedules:read`
- `schedules:write`
- `schedules:dispatch`
- `events:ingest`
- `runs:read`
- `runs:write`
- `approvals:write`

`*` is supported for an explicitly configured administrative credential.

## Audit identity

Identity-bearing fields are not accepted as client authority.

### Manual run

`initiatedBy` is always the authenticated principal id. The client supplies an `Idempotency-Key` header, which becomes the durable manual command id. The occurrence timestamp is generated by the server clock.

### Event ingestion

`source` is always the authenticated integration's configured source identity, falling back to its principal id. A JSON `source` field supplied by the client is ignored. This preserves Slice 7's source-scoped event deduplication boundary.

### Approval

The client only supplies the decision and optional note. The API reads the current runtime status and builds approval evidence from:

- the runtime's expected step id
- the runtime's expected revision id
- the runtime's expected role
- the authenticated principal id
- the server clock

The principal must hold that expected approval role, or `*`. A client cannot approve a different revision, claim a different role, or impersonate another reviewer.

## Routes

Public:

- `GET /healthz`

Automation registry:

- `POST /v1/automations`
- `GET /v1/automations/:automationId`
- `GET /v1/automations/:automationId/versions/:version`
- `POST /v1/automations/:automationId/versions/:version/activate`

Triggering and runs:

- `POST /v1/events`
- `POST /v1/runs/manual`
- `GET /v1/runs/:runId`
- `POST /v1/runs/:runId/approvals`
- `GET /v1/runs/:runId/result`

Schedules:

- `POST /v1/schedules`
- `GET /v1/schedules/:scheduleId`
- `POST /v1/scheduler/dispatch`

The terminal result route refuses to attach while a workflow is still running, delaying, or waiting for approval. This prevents ordinary API reads from becoming long-lived blocking requests.

## HTTP posture

- default listen host is `127.0.0.1`
- proxy trust is disabled by default
- request bodies are capped at 2 MiB by default and cannot be configured above 10 MiB
- responses carry `Cache-Control: no-store`
- responses carry `X-Content-Type-Options: nosniff`
- missing/invalid bearer credentials fail with `401` and `WWW-Authenticate: Bearer`
- valid credentials without required permission/role fail with `403`
- malformed request contracts fail with `400`
- domain rejections fail with `422`
- durable-runtime transport failures fail with `503` without leaking runtime internals

No CORS policy is enabled in this slice. A browser operator console must therefore make an explicit same-origin or trusted-proxy deployment decision rather than inheriting a permissive cross-origin default.

## Current non-goals

Slice 8 does not add:

- a browser dashboard
- OAuth/OIDC accounts
- sessions or cookies
- API-key persistence
- a second publication repository
- list/search pagination across all registry objects
- arbitrary scheduler mutation while a lease is active
- external TLS termination

Those should be added only when their product need is proven against this authority boundary.
